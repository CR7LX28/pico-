# Pico 历史上下文升级任务清单

目标：在可控的上下文预算内保留任务所需的信息。近期历史按内容大小选取，旧记录按用途压缩，长工具输出可以按需找回；规则压缩不够时，再生成任务摘要。

升级前基线：最近 6 条历史记录优先保留细节，`history` 初始预算为 5200 字符，完整 prompt 的目标预算为 12000 字符，单次工具输出在进入历史前可能被截断。归档中的 v3 方案单独视为参考，不作为当前实现。

执行约定：一次只实施指定的 Phase。每期完成该期的代码、测试和文档，再推进后续阶段；各期结果分别记录，便于判断收益来自哪一项改动。

- [x] **B01｜固定对照条件。** 保留当前固定 6 条策略。准备相同的历史记录和字符预算，覆盖短消息密集、长工具记录、重复读文件三类场景，记录改动前的呈现结果和字符数。
- [x] **B02｜核对评测入口。** 优先用现有上下文测试或确定性历史重放做对照。若所用复现入口仍导入旧的 `pico.metrics`，只修复该入口所需的路径与参数。脚本化对照与真实模型实验结果分开记录。
- [x] **C01｜让近期记录条数随预算变化。** 修改 `pico/context_manager.py` 的 `_render_history_section()`：从最新记录向前选取，按实际渲染长度计算近期范围，再用剩余空间呈现较早记录，最终按时间顺序输出。通过 `ContextManager` 的配置切换固定窗口与动态窗口，沿用 `history` 分区预算；第一期无需新增 CLI 配置。
- [x] **C02｜按完整事件处理工具记录。** 修改 `_compressed_history_entries()` 及相关渲染逻辑，让工具名、参数和结果一起参与取舍。遇到单条过长记录时先换成可理解的短表示，再考虑省略；旧历史继续支持重复读取折叠。保持会话原始记录和当前请求独立于渲染裁剪。
- [x] **C03｜记录保留与裁剪决策。** 在 prompt 元数据与 trace 中记录策略、分区预算、实际长度、保留条数，以及哪些记录被缩短或省略。报告区分预算值与实际占用值。

- [x] **E01a｜完成一期对照。** 在相同输入和预算下重放固定 6 条与动态窗口，记录保留条数、字符数、缩短或省略的记录。若短表示规则也发生变化，补充仅切换窗口策略的对照。运行相关测试和代码检查，记录结果；确定性重放用于比较上下文呈现。

## Phase 4｜按需任务摘要与 token 预算

**交付：**可区分估算与实测的 token 计量、按阈值触发的摘要、失败退路和相应的配置说明。
