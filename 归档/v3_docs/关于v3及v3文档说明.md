# 关于v3及v3文档说明

hi大家，抱歉拖更那么长时间。

这段时间一直在思考一个问题：就是当项目复杂度上来之后，如何平衡大家的学习门槛和项目深度。

两者其实是天然矛盾的，如果pico要继续深入下去，往novel harness靠近，肯定要增加很多复杂度

v3版本就是这么个设计初衷，大家可以看到基本很多的代码都是ai写的（codex/claude code），架构是我把控

我希望能将这个时间点，目前最佳的工程实践带给大家（毕竟codex/claude的开发者目前也不人工写代码了）

所以基于上述背景，我觉得重要的是：

1. 你了解当前主流harness的优秀实践，能在面试里讲trade-off，讲好方案设计
2. 通过benchmark和各类评测，以实验的思想来证明我们项目的效果好

因此后面v3的文档不会像main分支那样，我主要会从一个模块切入，跟各家harness进行对比，做实验，带大家走完从设计到评测的harness构建闭环。

在这个过程中，我觉得最好的工具就是你用的顺手的code agent

比如codex，比如claude code + deepseek/glm，这些我都是觉得不错的

然后**用提问的方式，精读代码实现，让AI把你分析方案，整个过程中你切去ide看代码的时间我觉得要尽量减少**。

**可以是你理清楚了设计和trade-off，再让AI给你展示重要的代码部分。（因为面试的时候是真的不需要你讲到具体一行代码怎么写的，不要把时间浪费在这里）**

今天起代码和文档会陆续更新，目前有的内容是：

1. 上下文（0625更新）
2. Memory
3. autoresearch式地优化system prompt
4. pico在harness benchmark上的表现

对应的话在简历上就能更新四部分描述，等总的实验跑完会更新出来，这部分内容做完其实就相当于一个新的项目了

我也陆续看到一些类似的课程开始用code agent去跟pico做类似的事情，但我保证v3更新完之后，我们在深度是绝对是领先其他code agent项目一大截的～
