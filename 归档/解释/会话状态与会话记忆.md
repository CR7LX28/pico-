# 会话状态与会话记忆

> **文档生成时间**：2026-08-05

## 背景

runtime 在推进一次执行时，需要同时维护两类信息：一类是**给模型看的对话流水**，让模型知道"之前发生了什么"；另一类是**给程序和人类看的运行状态**，回答"现在跑到哪了、第几轮了、怎么停的"。

这两类信息在 Pico 里分别由 **session history** 和 **TaskState** 承载，职责不同、生命周期不同、落盘文件也不同。

## 这篇要解决什么问题

- session history 里到底记什么，什么时候写，什么时候读
- TaskState 的 11 个字段各管什么，在主循环里怎么变
- 两者怎么配合，而不是互相替代

---

## session history

### 是什么

`self.session["history"]` 是个**列表**，存着本轮会话从开始到现在的所有对话记录。通过 `self.record()` 追加，落盘为 `session.json`。

### 里面记什么

每条记录是一个字典，按角色分三类：

| 角色 | 什么时候写 | 记录内容 |
|---|---|---|
| `"user"` | 用户每发一条消息 | `{"role": "user", "content": "...", "created_at": "..."}` |
| `"tool"` | 每次工具执行完毕 | `{"role": "tool", "name": "read_file", "args": {...}, "content": "结果...", "created_at": "..."}` |
| `"assistant"` | 模型给出最终答案 / 遇到 retry 提示 | `{"role": "assistant", "content": "...", "created_at": "..."}` |

### 在主循环里的写入时机

在 `agent_loop.py` 里可以串起来：

```
用户发消息  → record({"role": "user", ...})        # 第18行
模型调工具  → 执行完 record({"role": "tool", ...})   # 第145行
模型输出坏  → record({"role": "assistant", ...})     # 第179行（retry 提示）
模型给答案  → record({"role": "assistant", ...})     # 第184行（最终答案）
```

### 怎么被消费

每轮循环重建 prompt 时，`history_text()` 把 history 列表渲染成文本塞进 prompt，模型每轮都能看到"对话上下文"。近期条目保留更多细节，早期条目会被裁剪或去重（比如重复读同一文件只保留一次）。

### 生命周期

**跨 run 持续累积**。一次会话可以包含多轮 run，history 不会因为新 run 开始而清空，除非显式调用 `reset()`。

## TaskState

### 是什么

`TaskState` 是一个 Python `@dataclass`，用它兜住**单次 run** 的所有计数与状态。一次请求 = 一个 TaskState 实例，落盘为 `task_state.json`。

### 11 个字段

| 字段 | 类型 | 默认值 | 谁改 | 说明 |
|---|---|---|---|---|
| `run_id` | `str` | 必填 | 创建时固定 | 运行 ID，格式 `run_YYYYMMDD-HHMMSS-xxxxxx` |
| `task_id` | `str` | 必填 | 创建时固定 | 任务 ID，格式 `task_YYYYMMDD-HHMMSS-xxxxxx` |
| `user_request` | `str` | 必填 | 创建时固定 | 用户的原始请求文本 |
| `status` | `str` | `"running"` | `stop()` / `finish_success()` | 当前状态 |
| `tool_steps` | `int` | `0` | `record_tool()` 每次 +1 | 工具执行次数（只统计进入执行阶段的） |
| `attempts` | `int` | `0` | `record_attempt()` 每次 +1 | 模型被调用的总轮数 |
| `last_tool` | `str` | `""` | `record_tool()` 更新 | 最后一次调用的工具名 |
| `stop_reason` | `str` | `""` | `stop()` / `finish_success()` | 停止原因 |
| `final_answer` | `str` | `""` | `finish_success()` / `stop()` | 最终回答文本 |
| `checkpoint_id` | `str` | `""` | 主循环中外部赋值 | 检查点 ID（空串表示无） |
| `resume_status` | `str` | `""` | 创建时外部赋值 | 恢复状态：`no-checkpoint` / `full-valid` / `partial-stale` |

### 状态常量

**status 的四种取值：**

| 常量 | 值 | 含义 |
|---|---|---|
| `STATUS_RUNNING` | `"running"` | 正在运行 |
| `STATUS_COMPLETED` | `"completed"` | 正常完成（模型返回了 final answer） |
| `STATUS_STOPPED` | `"stopped"` | 被停止（达到步数上限或重试上限） |
| `STATUS_FAILED` | `"failed"` | 异常失败（模型错误等） |

**stop_reason 的全部取值：**

| 常量 | 值 | 含义 |
|---|---|---|
| `STOP_REASON_FINAL_ANSWER_RETURNED` | `"final_answer_returned"` | 模型返回了最终答案 |
| `STOP_REASON_STEP_LIMIT_REACHED` | `"step_limit_reached"` | 达到工具步数上限 |
| `STOP_REASON_RETRY_LIMIT_REACHED` | `"retry_limit_reached"` | 达到重试次数上限 |
| `STOP_REASON_MODEL_ERROR` | `"model_error"` | 模型调用出错 |
| `STOP_REASON_TOOL_TIMEOUT` | `"tool_timeout"` | 工具执行超时 |
| `STOP_REASON_APPROVAL_DENIED` | `"approval_denied"` | 审批被拒绝 |
| `STOP_REASON_DELEGATE_FAILED` | `"delegate_failed"` | 委派失败 |
| `STOP_REASON_PERSISTENCE_ERROR` | `"persistence_error"` | 持久化错误 |
| `STOP_REASON_RESUME_LOAD_ERROR` | `"resume_load_error"` | 恢复加载错误 |

### status 和 stop_reason 为什么分开

同一个 `stopped` 状态，原因可能是步数耗尽，也可能是重试过多。分开存，归因时就不会把"正常用完了配额"和"模型一直在输出垃圾"混成一团。

### 在主循环里的生命周期

`agent_loop.py` 中每一步都在操作 TaskState：

```
第20行  create(...)                         → 创建，status = "running"
第46行  task_state.record_attempt()         → attempts +1（每轮循环）
第46行  run_store.write_task_state(...)     → 写出 task_state.json（实时快照）
第141行 task_state.record_tool(name)        → tool_steps +1，更新 last_tool
第185行 task_state.finish_success(final)    → status → "completed"，stop_reason → "final_answer_returned"
第212行 task_state.stop_retry_limit(...)    → status → "stopped"，stop_reason → "retry_limit_reached"
第215行 task_state.stop_step_limit(...)     → status → "stopped"，stop_reason → "step_limit_reached"
```

### 两个工厂方法

| 方法 | 用途 | 调用位置 |
|---|---|---|
| `create(task_id, user_request, run_id?)` | 新建 TaskState，自动生成 run_id | `agent_loop.py` 第20行 |
| `from_dict(data)` | 从 `task_state.json` 反序列化还原 | 恢复 / 加载场景 |

## 两者关系总结

| 维度 | session history | TaskState |
|---|---|---|
| 是什么 | 对话流水（列表） | 运行状态（dataclass） |
| 记录什么 | 谁说了什么、工具返回了什么 | 跑到第几轮、调了多少工具、怎么停的 |
| 谁看 | **模型看**（每轮进 prompt） | **人和程序看**（不进 prompt） |
| 生命周期 | 跨多次 run 持续累积 | 每次 run 新建一个 |
| 落盘文件 | `session.json` | `task_state.json` |
| 核心方法 | `record()` / `history_text()` | `create()` / `record_attempt()` / `record_tool()` / `finish_success()` / `to_dict()` |

两者在 `agent_loop.py` 的每一轮循环里**并行写入**——模型调工具后，工具结果同时进 history（让下轮模型能看到）和触发 `record_tool()`（更新计数器）。最终，history 交给模型继续对话，TaskState 落盘供复盘和评估。
