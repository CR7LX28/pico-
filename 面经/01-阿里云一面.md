### 1. 7 类工具和 3 类运行工件分别是什么？

> Pico 有 7 类工具。读和定位有 `list_files`、`read_file`、`search`，改文件有 `write_file`、`patch_file`，执行命令用 `run_shell`，还可以通过 `delegate` 把小范围调查交给步数受限的只读子 Agent。每次运行有三类核心工件。`task_state.json` 看任务跑到哪了，`trace.jsonl` 看过程里发生了什么，`report.json` 看最终结果、停止原因和这次运行的统计。

| 工具 | 作用 |
| --- | --- |
| `list_files` | 枚举工作区文件，先定位目录和入口 |
| `read_file` | 按行读文件或已落盘的 shell 日志，长行可指定起始列 |
| `search` | 在工作区搜索内容，优先用 `rg` |
| `write_file` | 创建或覆盖文本文件 |
| `patch_file` | 按精确的旧文本替换一个代码块 |
| `run_shell` | 在仓库根目录执行带超时的命令，如跑测试 |
| `delegate` | 启动受步数和深度限制的只读子 Agent，取回调查结论 |

写文件、打补丁和执行 shell 受风险策略控制。子 Agent 到达深度上限后，工具注册表会隐藏 `delegate`。长命令日志可额外落盘，它是按需产生的附件。 [工具注册](../pico/tools.py) · [运行工件](../pico/run_store.py)

### 2. 上下文压缩具体是怎么做的？

> 我把会话保存和给模型看的上下文分开。每次调用前，Pico 按固定顺序拼接稳定前缀、工作记忆和任务状态、相关记忆、历史、当前请求。历史从最新往前，按实际渲染长度尽量保留完整事件。碰到放不下的记录，再尝试用短版本表示，最终仍按时间顺序呈现。旧的重复读文件记录可以折叠，新鲜的文件摘要可以复用，长命令日志用短预览加文件引用，模型需要时再读回。有效用户约束单独放进任务状态，优先于普通历史。

默认目标是 **12,000 字符**，历史初始预算是 **5,200 字符**。收缩时优先腾出低优先级空间，有任务状态时先收历史。当前请求完整保留，极端输入仍可能超出目标，元数据会标记。旧版固定最近 6 条，现在默认使用动态窗口。按模型计算 token 和按阈值生成任务摘要在升级清单中仍待完成。 [上下文实现](../pico/context_manager.py) · [升级清单](../docs/architecture/context-history-upgrade-checklist.md)

### 3. Checkpoint / resume 机制是怎么做的？

> 每次工具执行后以及运行收尾等节点，我会保存 checkpoint。它记录任务状态副本、目标、阻塞点、下一步、关键文件指纹和运行身份。续跑时，`--resume` 加载同一个 session，用当前工作区重新检查文件和运行配置。文件变了就标记旧读结果过期并要求重读，旧测试证据也要按当前工作区重新判断。接下来用这份上下文开一个新 run，让模型重新决定下一步。

`uv run pico --resume latest` 可恢复最近保存的会话。Session 保存历史、记忆和 checkpoint，写入时先生成临时文件再替换快照。运行身份包含模型、工具签名、审批策略、工作区指纹等。检查结果包括 `full-valid`、`partial-stale`、`workspace-mismatch` 和 `schema-mismatch`。恢复粒度是已保存的任务状态。若命令已产生副作用、进程却在记录结果前退出，需要先检查实际文件或外部状态，再决定是否重试。 [检查点](../pico/checkpoint.py) · [会话保存](../pico/session_store.py) · [运行循环](../pico/agent_loop.py)

### 4. 目前项目进度是什么样的，部署在哪里？

> Pico 已经做成可在仓库目录里运行的本地 Python CLI，支持单次任务和交互模式。模型调用、工具审批、会话恢复、运行记录和离线评测这条链路已经打通。最近完成了动态历史窗口、长日志落盘和跨轮约束保留。Pico 进程在用户机器上执行工具，模型服务独立配置，可以用本机 Ollama，也可以走兼容 API。

实际演示如果走了远端接口，说明用的是哪类后端。是否部署在实验室 GPU、是否有实际用户和运行规模，按自己确认过的信息回答。仓库给出的交付形态是本地 CLI，云端生产部署情况未核实。 [使用说明](../README.md) · [阶段进度](../docs/architecture/context-history-upgrade-checklist.md)
